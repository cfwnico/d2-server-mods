# Rune Exchange (暗黑破坏神 II 1.14d 符文置换特色插件)

## 1. 插件概述

`rune_exchange` 是专为现代化暗黑破坏神 II 1.14d 服务端定制开发的纯服务端注入插件（Feature DLL）。

### 核心功能
- **装备置换高级符文**：玩家将满足条件的暗金装备出售给 NPC（如第一幕阿卡拉）时，自动触发置换机制。
- **不可回购与原生防刷**：售出的装备由引擎原生直接销毁，**绝对无法从 NPC 商店回购**，彻底杜绝刷符文漏洞。
- **正常结算金币**：玩家出售装备时，游戏原生金币结算流程不受影响，正常获得金币奖励。
- **NPC 货架即时刷新**：NPC 商店页面会立即刷新出置换生成的指定随机符文（默认 18#~33#），供玩家在商店中正常回购。
- **聊天栏系统提示**：置换成功后，服务器会向该玩家客户端发送一条暗金色的英文公告提示（例如：`[Rune Exchange] Rune #28 spawned in shop! Remember to buy it back.`），提醒玩家及时回购。
- **全动态热重载（Hot-Reload）**：无需重启游戏服务端进程或容器 Pod，修改 `rune_exchange.ini` 后在下一次售卖交易时立即生效。
- **纯服务端实现**：遵循 MODDING 规范，客户端无需安装任何补丁或修改，原版客户端即可完美兼容体验。

$$P(Rune_i) = \frac{W_i}{\sum_{k=MinRune}^{MaxRune} W_k} \times 100\%$$

## 4. 部署与安装方法

### 4.1 服务端部署步骤
1. 将 `bin/rune_exchange.dll` 与 `bin/rune_exchange.ini` 拷贝至服务器的 Mod 挂载目录：
   ```bash
   # 宿主机路径（对应 k3s 容器内的 /mods/）
   /home/cfwd2/d2mods/rune_exchange.dll
   /home/cfwd2/d2mods/rune_exchange.ini
   ```
2. 确保文件具备读取权限：
   ```bash
   chmod 777 /home/cfwd2/d2mods/rune_exchange.dll /home/cfwd2/d2mods/rune_exchange.ini
   ```
3. 重启 GameServer 实例（通过 Kubernetes Rolling Restart 或 Helm）：
   ```bash
   sudo k3s kubectl rollout restart deployment/d2gs-1-14d -n realm
   ```

### 4.2 自动部署脚本参考 (`temp/deploy_mod.py`)
项目中已配套提供了自动化一键部署脚本 `temp/deploy_mod.py`，执行以下命令即可自动通过 SFTP 上传并触发 Pod 优雅重启：
```bash
python temp/deploy_mod.py
```

### 4.3 运行时日志排查
插件会在以下路径输出详细的操作与调试日志：
- 容器内：`/mods/rune_exchange.log`
- 宿主机：`/home/cfwd2/d2mods/rune_exchange.log`
- 查看命令：

## 6. 底层技术实现与逆向分析

### 6.1 封包拦截与分发 Hook
- 暴雪 1.14d `Game.exe` 中，客户端到服务端的封包处理表基址位于 `0x006E0EB0`（对应 Packet `0x33`：`SCMD_0x33_NpcSell`）。
- 原处理函数为 `0x0054BB20`。
- 本插件通过 `VirtualProtect` 替换该跳转表指针为自定义裸函数 `Hook_SCMD_0x33`，实现售卖封包的无侵入式拦截与预处理。

### 6.2 遵循暴雪原生符文之语/无形装备不可回购机制
在逆向 `D2GAME_NpcSell_579510`（`0x00579510`）过程中，发现引擎原生对装备是否能回购的检查逻辑：
```asm
0x00579624: mov dword ptr [ebp - 4], 1      ; 本地变量 can_buyback 默认为 1
0x00579660: push 0x100                      ; ITEMFLAG_CANNOT_STORE
0x00579666: call 0x6280a0                   ; CheckItemFlag
0x0057966f: mov dword ptr [ebp - 4], 0      ; 若包含，can_buyback = 0
0x005796b2: push 0x400000                   ; ITEMFLAG_ETHEREAL
0x005796b8: call 0x6280a0                   ; CheckItemFlag
0x005796c1: mov dword ptr [ebp - 4], 0      ; 若包含，can_buyback = 0
0x005796d4: call 0x55f590                   ; 检查是否镶嵌了宝石/符文（符文之语）
0x005796dd: mov dword ptr [ebp - 4], 0      ; 若有镶嵌，can_buyback = 0
0x00579720: je 0x5798da                    ; 当 can_buyback == 0 时直接跳往 0x5798da！
```
- **核心利用**：在插件调用引擎售卖前，给目标物品赋予标志 `dwItemFlags |= 0x00400100`。
- **效果**：原生引擎直接判定该物品为不可回购装备，自动跳过克隆 NPC 物品（`0x55A2A0`）和货架封包发送（`0x5762C0`），直接在 `0x5798DA` 将物品从玩家背包扣减并销毁，同时正常结算金币并向客户端发送交易确认包 `0x2A`，100% 原生安全无任何副作用。

### 6.3 Packet 0x26 封包解析器对齐
客户端接收 `0x26`（系统通知封包）时，长度解析器位于 `0x0052B98E`，处理函数位于 `0x0045DFC0`：
- **封包结构**：
  - `[0]`: `0x26`（Opcode）
  - `[1]`: `0x04`（Chat Type: 4 = 聊天栏系统公告）
  - `[2..3]`: `0x00, 0x00`
  - `[4..7]`: `0x00000000`（Unit ID）
  - `[8]`: `0x04`（Color: 4 = 暗金色 Unique）
  - `[9]`: `0x00`
  - `[10]`: `0x00`（发送者空字符串结尾 `\0`）
  - `[11..]`: 消息正文字符串（以 `\0` 结尾）
- **长度匹配**：解析器要求总长度严格等于 `12 + msg.len`。插件精确匹配该长度，消除了 TCP 流粘包与截断隐患。

### 6.4 NPC 商店物品动态生成
- 调用内部函数 `0x00576330`（`D2GAME_GenerateNpcItem`），以 `ilvl = 90` 参数生成符文，保证 1#~33# 全号段符文均能稳定挂载进 NPC 货架。
